# 16 · 工作区规则（Workspace Rules）

> 这份文档描述的是**已经实现并有测试守护**的规则，不是愿望。
> 修改工作区行为前先读它；改完之后**回来更新它**。
> 每条规则对应 `web/src/tabs.render.test.tsx` 里的一个测试。

---

## 1. 没有二级弹窗

**任何"你在里面工作"的界面都是 tab，没有例外——包括设置。**

弹窗表达不了文献工作的形态：读 PDF、做标注、就它提问、翻库，这些是**并行**发生
的，常常持续一小时。弹窗会抢走整个屏幕、堆叠起来很糟、关掉就丢状态。

允许存在的浮层只有三类，它们都**不是界面，而是一次交互**：

| 浮层 | 为什么不是 tab |
| --- | --- |
| 命令面板 | 打开就是为了立刻关掉 |
| 确认框 / 输入一个字符串 | 一次性回答，无状态可言 |
| toast、右键菜单、下拉 | 瞬时反馈 |

判据很简单：**关掉它会不会丢掉你正在做的事？** 会，就必须是 tab。

已按此规则搬迁的界面：设置、插件、状态、收藏夹编辑器、Zotero 导入、
图谱、必读缺口、阅读器、对话。

## 2. Tab 模型

### 2.1 一件事一个 tab

id 就是 `kind:target`（无 target 的界面 id 就是 kind）。**再次打开同一件事是聚焦，
不是新开。**

### 2.2 预览槽位（斜体）只有一个，且跨类型共享

斜体 = 这是一次**瞥一眼**。翻十篇论文不该留下十个 tab，所以下一次瞥一眼会
**顶掉**上一个，并且**保持它原来的位置**（否则 tab 条会在鼠标底下乱跳）。

关键点：这个槽位是**全局唯一**的，不是每种类型各有一个。否则每种类型都会各漏一个。

### 2.3 什么以预览打开，什么直接固定

| 打开方式 | 结果 |
| --- | --- |
| 单击列表里的论文 / 图谱节点 / 历史对话 | **预览**（斜体） |
| 新建对话、新建收藏夹 | **固定**——"新建"本身就是意图 |
| 设置、插件、状态、必读缺口、收藏夹浏览 | **固定**（它们是目的地，不是一瞥） |

### 2.4 什么会把预览变成固定

- 双击 tab 标题；
- **在里面写了字**——发出一条对话消息、做一个高亮。
  在一个界面里输入，是"这不是随便看看"的最强声明。

反向永远不会发生：**固定的 tab 不会退回预览。**

### 2.5 切换 tab 不改变任何 tab 的预览状态

从 chat 切到 library 再切回来，chat 还是原来的样子。切换只是切换。

### 2.6 每个 tab 记住自己在看什么

library 类型的 tab 各自拥有一份 scope（当前集合、选中项、滚动位置、搜索词）。
切走时保存、切回时恢复。**关闭时丢弃**——否则每开过一次 tab 就泄漏一份条目列表。

### 2.7 关闭之后去哪

右邻，没有右邻就左邻，都没有就回 library。这是所有编辑器的做法，肌肉记忆认它。

library tab 永久存在，关不掉。

## 3. 曾经踩过的坑（不要重犯）

### 3.1 对话 tab 从不使用预览槽位

用户报告"tab 跳转逻辑很混乱"，根因就在这里：`openConversation` 打开的是固定 tab，
于是**翻看三个历史对话就留下三个 tab**，而翻看三篇论文只留下一个。同一个手势
（在列表里点一下）在两个地方含义不同——混乱正是这么来的。

**教训：一个手势在整个应用里只能有一个含义。** 现在 13 条规则每条都有测试。

### 3.2 只测纯函数，测不出这类问题

`lib/tabs.ts` 的单元测试一直是绿的，因为纯函数从来没错。错的是**界面向它请求了什么**。
这类 bug 只有把整个工作台渲染出来、真的点下去才会现形——和当初拖放、图谱点击
是同一形状。

**教训：涉及交互的改动，测试写在 `*.render.test.tsx` 里。**

### 3.3 别的教训（散落在各处，集中记在这里）

- **迁移必须按名字应用，不能按位置。** 撤销过的迁移会永久占用它的编号；
  接替那个编号的迁移在见过前者的库上永远不会执行。见 `db.rs`。
- **离线性能探针必须先设上生产 PRAGMA**（64 MiB 页缓存 + mmap），
  否则测出来的加速比是探针的，不是用户的。见 `docs/15` 第 6 节。
- **聚合里的每一样东西都要付 N 次。** 谓词放在聚合内还是聚合外，可以差两个
  数量级以上。见 `docs/13` 末节。
- **前台 checkpoint 会让某次写入付出整份 WAL 的代价**（p95 是 p50 的一百倍）。
  `wal_autocheckpoint = 0`，交给后台 worker。见 `db.rs`。
- **`check` 这类"非空即通过"的断言，必须让错误答案为空**，否则错的字符串也算通过。
