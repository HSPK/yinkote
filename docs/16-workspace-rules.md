# 16 · 工作区规则（Workspace Rules）

> 这份文档描述的是**已经实现并有测试守护**的规则，不是愿望。
> 修改工作区行为前先读它；改完之后**回来更新它**。
> 每条规则对应 `web/src/tabs.render.test.tsx` 里的一个测试。

---

## 1. 没有二级弹窗

**任何"你在里面工作"的界面都是 tab，没有例外——包括设置。**

弹窗表达不了文献工作的形态：读 PDF、做标注、就它提问、翻库，这些是**并行**发生
的，常常持续一小时。弹窗会抢走整个屏幕、堆叠起来很糟、关掉就丢状态。

允许存在的浮层只有三类，它们都**不是界面，而是一次交互**：

| 浮层 | 为什么不是 tab |
| --- | --- |
| 命令面板 | 打开就是为了立刻关掉 |
| 确认框 / 输入一个字符串 | 一次性回答，无状态可言 |
| toast、右键菜单、下拉 | 瞬时反馈 |

判据很简单：**关掉它会不会丢掉你正在做的事？** 会，就必须是 tab。

已按此规则搬迁的界面：设置、插件、状态、收藏夹编辑器、Zotero 导入、
图谱、必读缺口、阅读器、对话。

## 2. Tab 模型

### 2.1 一件事一个 tab

id 就是 `kind:target`（无 target 的界面 id 就是 kind）。**再次打开同一件事是聚焦，
不是新开。**

### 2.2 预览槽位（斜体）只有一个，且跨类型共享

斜体 = 这是一次**瞥一眼**。翻十篇论文不该留下十个 tab，所以下一次瞥一眼会
**顶掉**上一个，并且**保持它原来的位置**（否则 tab 条会在鼠标底下乱跳）。

关键点：这个槽位是**全局唯一**的，不是每种类型各有一个。否则每种类型都会各漏一个。

### 2.3 什么以预览打开，什么直接固定

| 打开方式 | 结果 |
| --- | --- |
| 单击列表里的论文 / 图谱节点 / 历史对话 | **预览**（斜体） |
| 新建对话、新建收藏夹 | **固定**——"新建"本身就是意图 |
| 设置、插件、状态、必读缺口、收藏夹浏览 | **固定**（它们是目的地，不是一瞥） |

### 2.4 什么会把预览变成固定

- 双击 tab 标题；
- **在里面写了字**——发出一条对话消息、做一个高亮。
  在一个界面里输入，是"这不是随便看看"的最强声明。

反向永远不会发生：**固定的 tab 不会退回预览。**

### 2.5 切换 tab 不改变任何 tab 的预览状态

从 chat 切到 library 再切回来，chat 还是原来的样子。切换只是切换。

### 2.6 每个 tab 记住自己在看什么

library 类型的 tab 各自拥有一份 scope（当前集合、选中项、滚动位置、搜索词）。
切走时保存、切回时恢复。**关闭时丢弃**——否则每开过一次 tab 就泄漏一份条目列表。

### 2.7 关闭之后去哪

右邻，没有右邻就左邻，都没有就回 library。这是所有编辑器的做法，肌肉记忆认它。

library tab 永久存在，关不掉。

## 3. 曾经踩过的坑（不要重犯）

### 3.1 对话 tab 从不使用预览槽位

用户报告"tab 跳转逻辑很混乱"，根因就在这里：`openConversation` 打开的是固定 tab，
于是**翻看三个历史对话就留下三个 tab**，而翻看三篇论文只留下一个。同一个手势
（在列表里点一下）在两个地方含义不同——混乱正是这么来的。

**教训：一个手势在整个应用里只能有一个含义。** 现在 13 条规则每条都有测试。

### 3.2 只测纯函数，测不出这类问题

`lib/tabs.ts` 的单元测试一直是绿的，因为纯函数从来没错。错的是**界面向它请求了什么**。
这类 bug 只有把整个工作台渲染出来、真的点下去才会现形——和当初拖放、图谱点击
是同一形状。

**教训：涉及交互的改动，测试写在 `*.render.test.tsx` 里。**

### 3.3 Agent 有写权限，就必须有审计痕迹

Agent 现在可以**增删改查**整个库（17 个工具，其中 12 个会写）。这带来一条硬规则：

**每一次工具调用都画在它发生的位置**，夹在促成它的那句话和随后那句话之间，
而不是在回答末尾折叠成一份摘要。

理由不是好看。摘要丢掉的恰恰是让回答**可核查**的东西：**哪一步导致了哪一步**。
一个由你看不见的检索拼出来的答案，你没有办法验证它；而一个改动了你的库的动作，
你必须能追溯到究竟是哪句话让它发生的。

配套的三条：

- **写操作有标记**（accent 色边 + 徽标）。"这些里面哪些真的动了东西"是任何人
  看到 trace 的第一个问题。
- **参数直接可见，返回值折叠**。参数很短，且正是"到底问了什么"；返回值常是一整页 JSON。
- **默认可逆**：`trash_items` 是推荐路径，永久删除是**另一个**工具，
  描述里直说"不可撤销"，并且提示词要求除非用户明确要求，否则一律用回收站。

`/api/v1/agent` 会列出全部工具与其中的写工具，所以"它能改我的库吗"不用读源码就能回答。

### 3.4 长任务属于它的对象，不属于发起它的请求

一次 agent 回合可能跑半分钟。把它绑在一个 HTTP 请求上，意味着**切个 tab、刷新一下
就把模型已经在做的工作丢掉了**——模型无论如何都会算完，唯一的问题是还有没有人
在那里接住答案。

所以：`ask` 立刻返回；进度走事件总线（和其它所有变更同一条）；`GET …/run` 随时可读，
这正是新打开的页面能**重新接上**一个进行中回合的原因。

配套设计：

- **推整份状态，不推增量。** 状态很小（几个步骤加一行文字），而错过一个增量的客户端
  会永久性地不同步，并且**自己无从察觉**。
- **中断是循环在步骤之间检查的标志位，不是丢弃 future。** 已经发出的请求无论如何都会
  返回，扔掉它的答案只意味着以后要再付一次钱。
- **一个对话同时只能有一个回合**——第二个直接拒绝而不是排队。两个回合的工具调用会
  交织成没人读得懂的记录。
- **步骤从 run 持久化，不从 transcript 重建。** 于是"实时看到的回合"和"明天读回来的
  回合"是同一个东西，而不是两种可能漂移的渲染。

### 3.5 步骤显示：标题不动，内容向下长

一个步骤是**一行固定高度的标题栏**（工具名 + 参数 + 展开箭头），展开时内容长在
**它下面**。标题不动，因此上方的一切都不会移位——这是"读一份记录"和"追着记录
在屏幕上跑"的区别。这也是它不用 `<details>` 的原因：`summary` 是文档流的一部分。

- 步骤与回复**同一条左边界**，于是一个回合读起来是一列：思考、动作、思考、回答；
- **参数放在标题行**（很短，且正是"到底做了什么"），**返回值折叠**（常是一整页 JSON）；
- **模型的 reasoning 默认折叠**，且单独一类。它是**过程不是答案**，
  当作正文展示等于把草稿当结论。

### 3.6 和模型说话的代码只放一处（`yk-ai`）

参考 `pi-ai` 的分法：**provider 契约、消息类型、流式事件、各家方言**全部收进一个 crate。

在此之前它们散在三处：类型在 `yk-core`、chat 方言在 `yk-server`、embedding 方言在
`yk-search`。三个地方必须彼此吻合，而其中任何一个都**没法单独测试**——测 chat 方言
要拖起一个 HTTP 服务，测 embedding 要拖起一个数据库。

现在的分层：

```
yk-ai/
  types.rs           消息、工具、请求（每家 provider 共用一套）
  stream.rs          Delta：Text / Reasoning —— 各家差异到此为止
  provider.rs        ChatProvider / EmbeddingProvider 契约
  providers/openai.rs  OpenAI 方言（chat + SSE），也就是 Ollama/vLLM/LM Studio 说的话
  providers/embeddings.rs  本地哈希 + OpenAI 兼容
```

`yk-ai` 只从项目其余部分借一个 Error 类型，其它一无所知——它不知道文献库、条目或 SQLite。

**流式是主方法，不是可选项。** `complete(request, sink)` 是唯一的实现点，
`answer(request)` 是"我不要碎片"的便捷包装。这样 provider 必须**主动放弃**流式，
而不是**忘记**支持它。

### 3.7 "流式坏了"之前，先确认服务端是不是在缓冲

实测教训：开发用的这个端点发出的 SSE **格式完全正确**，199 个事件——但首个事件在
请求后 **7.46 秒**才到，且 199 个全部在 **0.05 秒内**涌完。它算完整个答案，然后
假装流式发出来。

这一侧没有任何东西可修。**唯一能分辨的办法是给到达时间打点，而不是读报文格式。**

### 3.8 别的教训（散落在各处，集中记在这里）

- **迁移必须按名字应用，不能按位置。** 撤销过的迁移会永久占用它的编号；
  接替那个编号的迁移在见过前者的库上永远不会执行。见 `db.rs`。
- **离线性能探针必须先设上生产 PRAGMA**（64 MiB 页缓存 + mmap），
  否则测出来的加速比是探针的，不是用户的。见 `docs/15` 第 6 节。
- **聚合里的每一样东西都要付 N 次。** 谓词放在聚合内还是聚合外，可以差两个
  数量级以上。见 `docs/13` 末节。
- **前台 checkpoint 会让某次写入付出整份 WAL 的代价**（p95 是 p50 的一百倍）。
  `wal_autocheckpoint = 0`，交给后台 worker。见 `db.rs`。
- **`check` 这类"非空即通过"的断言，必须让错误答案为空**，否则错的字符串也算通过。
