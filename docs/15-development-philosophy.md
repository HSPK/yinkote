# 15 · 开发哲学：持续重构

这份文档记录的是**怎么写**，而不是写什么。它由项目开发过程中反复出现的判断沉淀而来，
每一条都对应一次真实的代价——要么是已经付出的，要么是差点付出的。

---

## 1. 结构不是一次性决定，是持续的产物

最初的框架**几乎必然不是最好的**。它是在信息最少的时候做出的决定，而信息只会越来越多。

因此：

> **发现结构不对时，改结构，而不是在错的结构上继续叠加。**

判断"结构不对"的信号（都在本项目真实出现过）：

| 信号 | 本项目的实例 |
| --- | --- |
| 一个文件/对象承担了多个变更原因 | store 长到 961 行、159 个状态项 |
| 加一个功能要改三处不相干的地方 | 列定义散在表头、行、选择器里 |
| 某个需求"做不了"而不是"没做" | 两个标签页无法各搜各的 |
| 同一份知识出现两次 | 查询语言的中文别名写在解析器和补全里各一份 |
| 修一个 bug 要绕过设计而不是顺着设计 | 拖放载荷在派发前就被清空 |

叠加的成本是复利的：每一层都让下一层更难改。重构的成本是一次性的。

### 反例同样重要

不要为了"更干净"而重构。触发重构的应当是**具体的摩擦**，不是审美。
没有摩擦的重复代码可以先留着——过早抽象比重复更难拆。

---

## 2. 让错误的状态无法表示

优先级顺序：

1. **类型层面不可能** —— 最好
2. **测试会失败** —— 次之
3. **运行时报错** —— 可接受
4. **静默出错** —— 不可接受

实例：

- `State extends Scope`，初值来自 `emptyScope()`：新增一个标签页字段，不可能只加一处。
- `SCOPE_KEYS` 由真实的 scope 对象派生，而不是手写列表：两者不可能不一致。
- i18n 参考语言定义键类型：某个语言漏翻是**编译错误**，不是运行时 `[missing]`。
- 表头和行共用一份 grid 定义：给一个加列而忘了另一个，是不可能的而不只是显眼的。

**静默出错是最贵的**。拖放那个 bug 里，高亮走的是另一条代码路径、照常工作，
所以手势看着完全正确、就是没反应。这类问题只有断言才抓得住。

---

## 3. 测试守护的是判断，不是行数

每个测试应该回答"如果这条被违反了，会出什么事"。测试名写成**结论**而非动作：

```rust
// 好：说明了为什么这条重要
fn a_field_value_may_contain_spaces_when_quoted()
fn stops_at_the_step_budget_and_admits_it()
fn still_has_the_payload_after_the_drag_has_been_torn_down()

// 差：只描述了做了什么
fn test_parse()
fn test_drop()
```

三类特别值得写：

1. **性能特征断言**：`EXPLAIN QUERY PLAN` 断言外层循环是 FTS 表。
   这类 bug 返回**正确结果**、只是慢 3000 倍，只有计划断言抓得住。
2. **不变量守护**：英文词条表不得含 CJK；`src/i18n` 之外的源文件不得含 CJK。
   顺手抓出了插件控制台里一对残留的全角括号。
3. **回归的形状**：不只测修好的那个 case，测**那一类**。
   dropZone 的测试专门覆盖"拖拽已销毁后再派发"。

---

## 4. 编译器和 linter 的警告是信号，不是噪音

> **消掉一个警告之前，先问它在告诉你什么。**

真实教训：`readDrop` 的 unused import 警告，说明的是"载荷已经没人读了"——
即拖放功能已经断了。当时我删掉了 import 而不是听它说话，于是功能静默失效。

同理：`forget_files` 的 dead_code 警告暴露了"删除条目会泄漏磁盘文件"。

---

## 5. 边界处诚实，不要替下游猜

- **服务端不决定显示语言**。默认对话标题、默认文库名、抓取源标签一律语言中性，
  占位文案由客户端出——只有客户端知道用户读哪种语言。
- **宿主只排序，不解释**。只有插件知道 Q1 胜过 Q4、中科院 1 区最好，
  所以 rank 由插件给，取反在插件那边做。
- **能力不足要说出来**。徽章排序上限 2000 条，超出时用响应头声明，
  而不是悄悄返回一个错误的顺序。Agent 步数用尽时 `truncated: true`。
- **拒绝猜测胜过猜错**。抓取 PDF 时，普通落地页不猜——
  把登录页当论文下载回来，比直接问用户更糟。

## 6. 性能是设计，不是事后调优

三条反复验证的经验：

1. **测量之前不要猜**。模糊搜索 18 秒，SQLite 本身 <1ms——问题在查询计划。
2. **写路径共享的资源要分片**。后台 embedding worker 一次提交 4000 行，
   独占唯一的写锁，把交互写入的 p95 拖到 386ms。改成 200 行一批 + yield。
3. **缓存要能精确失效**。标签聚合按 library version 计数器缓存，
   任何写入都会 bump 它，所以失效是精确且免费的——不需要 TTL。

前端同理：pdf.js 动态导入，480 KB 不进初始包；多数会话根本不会打开论文。

### 测量环境必须和真实部署一致，否则你优化的是探针

一次真实的教训，值得完整写下来。

关键词检索里，FTS 命中之后要 join `items` 校验 library 和 deleted。用一个独立
小程序打开同一个 10 万条目的库测量，这个 join 占了查询的一半以上（44ms → 21ms），
于是加了一条只含 `(id, library_id, deleted)` 的覆盖索引，`INDEXED BY` 强制使用，
离线复测 **36ms → 21ms**，看起来是干净的 33% 胜利。

接进服务器，端到端基准**纹丝不动**。

原因是：探针用的是 SQLite 默认的 2 MB 页缓存，而服务器每条连接都设了
`cache_size = -65536`（64 MiB）和 `mmap_size = 256 MiB`。默认缓存下，每次按
rowid 回表都要换页，join 当然贵；64 MiB 缓存下那些行本来就在内存里，覆盖索引
一分钱也省不下（21.4ms vs 21.1ms）。

被测出来的不是"join 很贵"，而是"我的探针缓存太小"。

**规则**：任何离线性能探针，必须先把生产连接的 PRAGMA 原样设上，再开始计时。
否则你得到的加速比是探针的，不是用户的。

改动已整体回退——一条买不到任何东西的索引不是中性的：它要占磁盘、要在每次写入
时维护、还留下一个脆弱的 `INDEXED BY` 提示让后来者困惑。**没有收益的优化是负债。**

同一轮里另一个负面结果也记在这里：把 library 过滤改写成
`items_fts.rowid IN (SELECT id FROM items WHERE library_id = ?)` 看着很自然，
实测 **15 秒**（对比 21 毫秒）。不要用它。

## 7. 注释解释判断，不解释操作

代码已经说了**做什么**。注释要说的是**为什么是这样而不是别样**，
尤其是那些"看起来可以更简单"的地方——那正是未来的人会去"简化"掉的地方。

```rust
// 好：解释了一个反直觉的选择
// CROSS JOIN 把虚拟表钉成外层循环。普通 JOIN 会让规划器从 items 驱动，
// 扫全部 10 万行、每行探一次 FTS 索引。

// 差：复述了代码
// 执行 CROSS JOIN 查询
```

不需要解释的代码就不要注释。

## 8. 交互形态服从工作方式

弹窗、标签页、面板不是审美选择，是对"用户会怎么用"的判断：

- **读论文、做标注、就它提问是同时进行的**，往往持续一小时 → 标签页。
- **改一个偏好是岔开一下** → 弹窗。
- 侧栏是**快捷入口不是清单** → 超过一屏就折叠，另开可搜索可排序的浏览器。
- 预览标签（斜体）解决的是"翻二十条结果留下二十个标签"。

判断标准：**这件事会持续多久？会不会需要同时看别的东西？**

---

## 9. 每一轮都必须可运行

```bash
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cd web && npm run build && npm test
bash scripts/smoke.sh
```

全绿才提交。冒烟测试打的是**真实运行的服务**，不是 mock——
它抓到过几次单元测试结构上看不见的问题（配置未加载、路由未注册、迁移未执行）。

提交信息写**为什么**，不写改了哪些文件——文件列表 git 已经有了。

---

## 10. 小结

| 原则 | 一句话 |
| --- | --- |
| 持续重构 | 结构不对就改结构，不要在错的结构上叠加 |
| 不可表示 | 优先让错误状态在类型层面不存在 |
| 测试判断 | 测试名是结论，覆盖的是一类而非一个 |
| 听警告 | 消警告前先问它在说什么 |
| 边界诚实 | 不替下游猜，能力不足要声明 |
| 性能是设计 | 先测量，分片写路径，精确失效 |
| 注释判断 | 解释为什么，不解释做什么 |
| 形态服从用法 | 持续的事给标签页，岔开的事给弹窗 |
| 每轮可运行 | 全绿才提交 |
